# Markdown-to-film implementation boundary

The six skills supply creative intent and workflow constraints. A planner reads the selected skill/profile plus bounded evidence, proposes a structured brief and EDL, and a validator rejects unsupported or out-of-bounds work. The render adapter produces pixels/audio; the job service handles authorization and spend. None of those roles can be replaced by “send the Markdown to a Worker”.

The included helper checks a small typed planning contract with a synthetic sample. It makes no API calls, executes no commands, installs nothing, writes no files and cannot validate media authenticity. The actual JOVRA renderer, synchronization and cloud service remain work for Claude.

Build the first complete source journey before extending effects: real file → trusted manifest → manually selected keepers → validated basic cuts and primary court audio → fully decoded film → private playback/download. Then add reviewed sync, replay/annotation/title primitives, clean/effects alternates and advanced job hosting. Extend contracts and meaningful verification alongside each operation.

For model input, retrieve only authorized relevant clips/frames/transcripts/observations. Preserve original time/provenance. Do not put complete 40-screen HTML/base64 images into context. Keep creative intent and typed plan separate from trusted source manifests and spending authorization.

The earlier backend-media-design brief remains the detailed architecture/cost proposal. This v2 package adds creative operating skills and a continuation path; it does not supersede the current app’s ADRs automatically.
