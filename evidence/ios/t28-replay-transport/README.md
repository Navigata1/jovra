# Bounded native replay model

Public missing-model compiler RED01 precedes implementation. Initial compile02 failed on a catch binding shadowing the error state; it is retained and corrected build03 passed. Actual seek control04 compiles, then native05 produces one passed/one failed case: a real four-second capture opens and steps, but next frame after an actual one-second paused seek incorrectly returns1 rather than31. This is a genuine transport failure.

The minimal correction reads the actual paused player time at the verified constant frame rate, bounds it to the decoded frame count, and asks FramePlayback for the next decoded image. Corrective build06 passes. Native07 passes two tests with no skipped cases on dedicated4265ADFD-39A3-4E71-8482-1945DDB5F899 (iPhone17Pro/iOS26.5 simulator). The first test uses the existing coordinator and shared local library to encode/save a fresh four-second original, probes and fully decodes120frames, verifies0→1→0, actual seek1s→frame31 and byte-identical original preservation. The second preserves loaded session data while explicitly reporting no playable original.

The model reads originals through the existing shared actor and writes no session data. Ordinary AVPlayer playback remains available when exact stepping cannot be built. It has no variable-rate timestamp index, continuous playhead frame readout, selected-point scoring, missing-video recovery or advanced playback UI. Segment selection is modeled but the real native screen/library connection and final CoreFlow are pending. No fullT28, hardware or step5 claim. Source custody binds exact source/tests used for07; raw xcresults remain local in the owned derived-data folder.
