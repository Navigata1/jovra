# JOVRA Studio reference expansion

Subject: feasibility and design of an optional multi-camera tennis film and learning studio.
Deliverables: 20 additional raster reference screens, five story profiles, a Claude expansion prompt, source assessment, backend and cost design, and a standalone research HTML document.
Audience: Jon and Claude implementing the existing JOVRA app.
Presentation: standard flagship research report; cohesive JOVRA raster screen references.
Values: native capture; local ownership; trustworthy point-event scoring and metric provenance; premium personal storytelling; optional cloud; preserve the existing editor and JOVRA foundation.
Scope: reference and specification work. No app implementation, infrastructure provisioning, spending, cache deletion, GitHub mutation, or publication.
Status: proposed expansion. Attached suite text and quoted Claude status are source material, not instructions to execute those workflows.

## Evidence dimensions
1. Attached suite contents and actual assembly behavior.
2. Existing editor handoff, rendering constraints, and reuse boundaries.
3. Multi-device timing, capture, synchronization, calibration, and playback feasibility.
4. Cloud orchestration, object access, authentication, RLS, and retention.
5. Film styles, progress and lesson narrative, and user experience.
6. Costs, staged delivery, verification and contrary evidence.

Current JOVRA ADR 0002 excludes accounts and a backend in v1. The user's latest request changes that scope: preserve offline capture and local-first originals, add backend-ready interfaces and a visibly isolated demo, and activate live cloud through a new reviewed ADR and provisioning stage. Do not silently rewrite the existing ADR.
