# JOVRA Tennis

Record tennis, find the point that matters, understand trustworthy metrics, practise with purpose, and
own your video. Tagline: **See your game.** iOS first (SwiftUI + AVFoundation + Vision), then Android
(Kotlin + Jetpack Compose + CameraX + Media3). The two apps share contracts in `spec/`, not code.

## Hard rules

1. **Honest analysis.** Never fabricate metrics. Every displayed number is computed from stored events and
   carries its provenance (`manual`, `estimated`, `reviewed`, `validated`) via the capability registry.
   Sample/demo data is always visibly labelled "Sample". No spin RPM, no 3D biomechanics, no injury or
   medical claims, no officiating-grade line calls.
2. **Local first.** Originals are saved on the device before anything else happens. Google Drive is an optional
   user-owned archive, never the database and never the analysis engine. No raw video leaves the device by default.
3. **Recording never blocks on analysis, network, microphone or account.** Video stays viewable when analysis fails.
4. **Corrections propagate.** Editing a point recomputes every later scoreboard state, stat and export. The original
   automatic result and the user edit are stored separately.
5. **No secrets in the client.** OAuth client IDs come from configuration; tokens live in Keychain / EncryptedSharedPreferences.
6. **Brand hygiene.** Manufacturer names appear only as user-entered text. No third-party logos, no implied sponsorship,
   no professional players' likenesses.
7. **Public contact (IDC Rule 07).** The only contact address shown anywhere is `hello@islanddevcrew.com`, as text. Never a
   `mailto:` link, never a personal address, in code, copy, manifests or commit metadata.
8. **Accessibility is a feature.** 44×44 pt targets, Dynamic Type, VoiceOver labels, Reduce Motion, increased contrast,
   meaning never carried by colour alone.
9. **Evidence, not claims.** A ticket is done when a check that could fail has passed. Simulator success, device success,
   ML validation and store readiness are reported separately. Unverified work is labelled unverified.

## Parallel-work rules

- The Xcode project is generated by XcodeGen from `ios/project.yml`; never commit or hand-edit `*.xcodeproj`.
  Sources are globbed by folder, so adding a file never needs a project edit.
- One feature per folder (`ios/Jovra/Features/<Feature>/`). Shared UI lives in `ios/Jovra/DesignSystem/`.
- Disk on the build machine is tight. Build with `-derivedDataPath` inside your worktree and delete it when done.
